## Patterns

### PATTERN-010: Bbox Center Calculation Operator Precedence Bug - RESOLVED

| Field | Value |
|-------|-------|
| **Status** | Resolved |
| **Severity** | Critical |
| **Impact** | Robot world positions computed incorrectly; planned paths start from wrong location and go off screen |
| **Component** | `cmd/main.go`, `cmd/demo_mode.go` |
| **Pattern** | Yes |

**Symptom:**
Paths generated by A* planner go off screen to the right instead of connecting the robot to its destination.

**Root Cause:**
`track.Bbox` stores `[X1, Y1, X2, Y2]` (corner coordinates). The center calculation `track.Bbox[0]+track.Bbox[2]/2` computes `X1 + (X2/2)` due to Go's operator precedence (division before addition), instead of the correct `(X1+X2)/2`.

**Pattern:**
Always use explicit parentheses around additions before division to avoid operator precedence issues.

**Fix Applied:**
```go
// Before:
px, py := track.Bbox[0]+track.Bbox[2]/2, track.Bbox[1]+track.Bbox[3]/2

// After:
px, py := (track.Bbox[0]+track.Bbox[2])/2, (track.Bbox[1]+track.Bbox[3])/2
```

## Resolution Procedures

### When Fixing a Bug

1. Add bug entry to this file with ID (e.g., `GOCV-001`)
2. Describe symptom, root cause, and fix
3. Update checklist if new pattern applies
4. Create unit tests to prevent regression
5. Create integration tests if applicable
6. Mark bug as resolved with date and PR#
7. Move resolved entry to ARCHIVED_BUGS.md

### Bug ID Format

- **GOCV-XXX**: GoCV/OpenCV related issues
- **DET-XXX**: Detection related issues
- **PIPELINE-XXX**: Pipeline integration issues
- **TEST-XXX**: Test coverage issues
- **CAM-XXX**: Camera related issues
- **UI-XXX**: User interface issues
- **DOC-XXX**: Documentation issues
- **CONFIG-XXX**: Configuration issues
- **PERF-XXX**: Performance issues
- **PATTERN-XXX**: Recurring bug patterns (keep in BUGS.md even when resolved)
